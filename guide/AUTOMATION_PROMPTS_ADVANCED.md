# PAP 자동화 운영체제 — 15개 프롬프트의 고차원 디벨롭

> 원본(AUTOMATION_PROMPTS_01-15.md)은 "사람이 복붙하는 단일 프롬프트"다.
> 이 문서는 그것을 **자율 운영 시스템(Agentic OS)** 으로 승격시킨다.
> 차이는 4가지: ① 1회 실행 → 상시 루프, ② 단일 AI → 역할 분리된 다중 에이전트,
> ③ 출력 → 데이터베이스에 축적되는 자산, ④ 지시 수행 → 스스로 성과를 측정하고 다음 행동을 제안.

---

## 0. 아키텍처: 4계층 구조

원본 15개는 전부 아래 4계층의 부품이다. 부품을 따로 쓰지 말고 계층으로 연결하는 것이 고차원화의 핵심.

```
[감지 Perception]  05 가격 · 14 트렌드 · 04 리서치 · 07 영상요약  → 세상 데이터 수집
[판단 Reasoning]   13 분석 · 06 리포트 · 09 요약               → 의미·우선순위 결정
[실행 Action]      01 이메일 · 08 발표 · 12 릴스 · 15 답장      → 콘텐츠·응대 생산
[통제 Governance]  02 회의록 · 03 일정 · 11 파일 · 10 명세      → 조직 기억·질서 유지
```

공통 승격 원칙 (모든 항목에 적용):
1. **크론화** — 사람이 시키지 않아도 정해진 시각에 돈다 (Vercel cron / Cowork 예약 작업)
2. **DB 축적** — 결과를 Supabase 테이블에 쌓아 시계열 자산으로 만든다 (growth_reports 패턴)
3. **자기검증** — 생산 에이전트와 별개의 검증 에이전트가 출력을 공격한다 (주간 에이전트 평의회 패턴)
4. **인간 게이트** — 발송·게시·삭제·결제는 항상 사람이 마지막 버튼 (이미 우리 운영 원칙)

## 감지 계층

### 05 → 경쟁 매거진 인텔리전스 (가격 → 콘텐츠 경쟁력 모니터링)

원본은 커머스용 가격 추적. 매거진에게 '가격'은 **경쟁지의 콘텐츠 성과**다.

- [대상] 아이즈매거진·하입비스트KR·데이즈드KR 등 경쟁 계정의 공개 지표(게시 빈도, 형식 믹스, 훅 문형, 해시태그 전략)를 주 1회 수집.
- [정규화] '주간 게시 수 / 릴스 비율 / 평균 좋아요 / 캡션 첫 줄 유형'으로 테이블화해 `competitor_snapshots`에 누적.
- [탐지] PAP 대비 격차가 2주 연속 벌어지는 지표만 골라 z-score로 랭킹, "그들이 시작했고 우리가 안 하는 것 1가지"를 매주 특정.
- [연결] 결과를 기존 성장 진단(growth_reports)에 `competitive` 섹션으로 주입 → 데일리 피드백이 경쟁 맥락까지 반영.

### 14 → 트렌드 → 발행 파이프라인 직결

원본은 Notion에 쌓고 끝. 승격판은 **트렌드가 곧바로 기사 초안이 되는** 파이프라인.

- [수집] 주 2회 패션위크 일정·브랜드 캠페인·셀럽 뉴스를 키워드 수집, 이미 다룬 주제는 제목 유사도로 자동 제외.
- [판정] '뜨는 것 3 / 지는 것 1'에 각각 **PAP 적합도 점수**(우리 독자층·톤 매치 0~10)를 매기고 근거 한 줄.
- [생산 연결] 적합도 8+ 항목은 pap-article 스킬 형식의 기사 초안 + 에디토리얼 커버 훅 문장까지 자동 생성해 어드민 draft로 저장.
- [학습 루프] 발행 후 7일 조회·공유 수를 회수해 적합도 점수 모델을 매달 보정 — "예측이 맞았나"를 시스템이 스스로 채점.

### 04 → 적대적 이중 리서치 (Adversarial Research)

원본은 요약 담당 1명. 승격판은 **서로 공격하는 2명 + 판정자**.

- [구조] 에이전트 A가 자료를 수집·주장하면, 에이전트 B는 반대 증거와 출처 결함만 찾는다. 판정자 C가 살아남은 사실만 채택.
- [등급] 모든 사실에 신뢰 등급(1차 출처/2차 인용/미확인 소문)을 태깅 — 매거진에 치명적인 '셀럽 오보'를 구조적으로 차단.
- [산출] '확정 사실 / 논쟁 중 / 오보 위험' 3단 보고서. 기사화 가능 여부를 결론으로 명시.
- [적용] 셀럽 뉴스·브랜드 이슈 기사 작성 전 필수 관문으로 배치 (Pepperit 데일리 뉴스에 특히 중요).

### 07 → 멀티모달 콘텐츠 리퍼포징 엔진

원본은 영상→글 단방향. 승격판은 **1개 소스 → N개 채널 형식** 방사형 변환.

- [입력] 유튜브 링크·쇼 영상·인터뷰 무엇이든 받아 핵심 논지·인용 3개(타임스탬프)·비주얼 포인트를 구조화.
- [방사] 같은 소스에서 ① 웹 기사(SEO 제목 2안) ② IG 캡션(한국어 훅 첫 줄 형식) ③ 릴스 대본(12번 연결) ④ Pinterest 핀 설명을 동시 생성.
- [일관성] 4개 산출물의 사실관계가 서로 어긋나지 않는지 교차 검증 후 출고.
- [효과] 콘텐츠 1개당 노출 표면 4배 — 제작 시간은 동일.

## 판단 계층

### 13 → 예측·이상탐지 분석가 (이미 PAP에 구축됨 → 확장)

원본의 '집계+해석'은 이미 우리 growth-report(선형회귀 slope, z-score, 7일 예측)로 구현돼 있다. 다음 단계:

- [인과 가설] 지표 변화를 이벤트 로그(게시물 발행, 광고 시작, 알고리즘 변경)와 자동 대조해 "무엇 때문인지" 후보를 랭킹.
- [반사실 질문] "광고를 안 했다면 이번 주 가입은?" 같은 반사실 추정을 추세선 외삽으로 답변 (growth-ask 확장).
- [실험 설계] 이상치 발견 시 원인 검증용 A/B 실험(예: 훅 문형 2종 교차 게시)을 스스로 설계해 제안.
- [월간 메타분석] 30일치 데일리 피드백을 다시 읽고 "반복 지적됐지만 개선 안 된 것"을 경영 안건으로 승격.

### 06 → 자가 서술형 경영 브리핑

원본은 주간 숫자 메일. 승격판은 **서사가 있는 경영 브리핑**.

- [통합] 웹(GA4·growth_reports) + IG(도달·공유) + 광고(지출·참여단가) + 수익(어필리에이트 클릭)을 하나의 주간 스토리로 결합.
- [서사] '이번 주의 한 문장 → 잘된 것 2 / 안된 것 2 → 원인 → 다음 주 베팅 1개' 구조. 숫자는 근거로만 인용.
- [결정 요청] 대표가 결정해야 할 것만 분리해 '예/아니오로 답할 수 있는 질문' 형태로 최대 3개 제시.
- [발송] 매주 월 07:30 KST 메일 초안 생성 → 임시보관함 (기존 데일리 크론과 동일 패턴, 주간 버전).

### 09 → 커뮤니케이션 트리아지 + 약속 추적기

원본은 하루 요약. 승격판은 **약속이 이행됐는지까지 추적**.

- [트리아지] 결정/요청/질문 분류에 더해, 각 항목의 마감·담당·의존관계를 추출해 `commitments` 목록으로 관리.
- [추적] "3일 전 요청받고 아직 응답 없는 것"을 자동 부상 — 잊혀서 죽는 협업 건 제로화.
- [외부 확장] 슬랙이 없으면 이메일·인스타 DM 협업 문의에 같은 구조 적용 (크리에이티브팀 협업이 많은 PAP에 적합).
- [주간 집계] '우리가 빚진 응답 / 상대가 빚진 응답' 대차대조표로 매주 마감.

## 실행 계층

### 01 → 수익 신호 감지 이메일 파이프라인

원본은 분류+초안. 승격판은 **이메일함을 영업 파이프라인으로** 취급.

- [신호] '긴급/일반/보관' 위에 **수익 신호 레이어** 추가: 브랜드 협찬 문의·광고 집행 문의·프레스 초청은 별도 트랙으로 승격.
- [CRM화] 수익 신호 메일은 발신 브랜드·요청 유형·추정 단가를 추출해 파이프라인 시트에 자동 기록 (문의→협상→계약 단계 관리).
- [맞춤 초안] 답장 초안에 해당 브랜드가 등장한 우리 에디토리얼 링크와 관련 지표(도달·저장)를 자동 첨부 — 세일즈 자료가 붙은 답장.
- [불변 규칙] 금액 단정 금지, 자동 발송 금지, PAP(38만)과 Pepperit(14만) 지표 절대 합산 금지.

### 08 → 브랜드 세일즈 덱 팩토리

원본은 범용 PPT. 승격판은 **문의 브랜드별 맞춤 미디어킷 자동 조립**.

- [입력] 브랜드명 하나만 주면: 그 브랜드가 태그된 우리 콘텐츠·성과 지표·유사 브랜드 협업 사례를 DB에서 자동 수집.
- [구성] '브랜드의 문제(도달하려는 고객) → PAP 독자와의 교집합 → 증거(우리 성과) → 협업 상품 3안 → 다음 단계' 설득 구조.
- [이원화] PAP용(하이패션·에디토리얼 톤)과 Pepperit용(K-pop Z세대 톤) 템플릿 분리 — 절대 한 덱에 혼합하지 않음.
- [출력] .pptx + 1장짜리 PDF 요약본 동시 생성. 단가표는 빈칸으로 두고 사람이 기입.

### 12 → 에디토리얼 → 릴스 자동 각색 스튜디오

원본은 대본→컷 분할. 승격판은 **기존 자산(에디토리얼 86편+)을 릴스로 재생산하는 공장**.

- [소스 선정] 조회·저장 상위 에디토리얼부터 자동 선별 (성과 검증된 소재만 영상화 — 실패 확률 최소화).
- [각색] 화보 서사를 '훅(1.5초) → 전개 3컷 → 반전/공개 → CTA' 5~7컷 구조로 변환, 컷별 화면지시·자막·영문 생성 프롬프트 표.
- [브랜드 규칙] 자막 톤은 IG 캡션 훅 문형과 통일, 마지막 컷은 항상 '전체 스토리는 프로필 링크에서'.
- [측정] 릴스 게시 후 원본 에디토리얼 페이지 유입 변화를 추적해 "영상화 가치가 높은 화보 유형"을 학습.

### 15 → 제출(Submission) 큐레이션 어시스턴트

원본은 상담 답장. PAP의 실제 폼은 **크리에이티브팀 에디토리얼 투고**다.

- [1차 심사] 투고가 들어오면 포트폴리오 링크·컨셉·크레딧 완결성을 체크리스트로 검토, 부족 항목은 정중한 보완 요청 초안 작성.
- [적합도] 우리 아카이브와 대조해 '유사 화보 존재 여부 / 최근 3개월 무드 겹침 / 채워지는 갭'을 판정 근거로 첨부.
- [양방향] 승인 초안엔 예상 발행 볼륨(분기)·캡션 계획을, 반려 초안엔 커뮤니티 참여 초대(리젝 인재풀 → 커뮤니티 활성화 전략과 연결)를 포함.
- [규칙] 확정 통보는 절대 자동 발송하지 않고 어드민 리뷰 큐에만 적재.

## 통제 계층

### 02 → 조직 기억 시스템 (Decision Ledger)

원본은 회의록 정리. 승격판은 **결정의 이력과 결과를 잇는 원장**.

- [원장화] 모든 결정을 '결정 / 근거 / 반대 의견 / 예상 결과 / 검증 시점' 5필드로 기록 — 회의록이 아니라 의사결정 데이터베이스.
- [회수] 검증 시점이 되면 자동으로 그 결정을 다시 꺼내 "예상대로 됐나?"를 실제 지표와 대조 (예: 볼륨 분기제 전환, 광고 타겟 설계).
- [패턴] 분기마다 '우리가 반복하는 판단 오류'를 추출 — 조직이 같은 실수를 두 번 하지 않게.
- [검색] "작년에 왜 이걸 안 하기로 했지?"에 한 줄로 답할 수 있는 상태 유지.

### 03 → 편집 일정 오케스트레이터

원본은 개인 일정 등록. 승격판은 **발행 리듬 전체의 지휘자**.

- [리듬 관리] 주간 목표(에디토리얼 5·기사 5·필름 1)와 실제 발행 페이스를 대조해 일정 슬롯을 선제 배치 (growth audit의 pace 체크와 직결).
- [충돌 지능] 단순 겹침 경고를 넘어 '이번 주 패션위크 → 기사 슬롯 2배, 화보 발행은 다음 주로' 같은 맥락 재배치 제안.
- [분기 이벤트] 볼륨 마감(분기말)·커버 선정·광고 리뷰 같은 반복 마일스톤을 자동 생성, D-7/D-1 준비물 체크리스트 브리핑.
- [금요 브리핑] 다음 주 전체를 '발행 계획 + 마감 위험 항목' 중심으로 한 화면 요약.

### 11 → 디지털 자산 라이브러리 (DAM)

원본은 파일 정리. 승격판은 **재사용 가능한 자산 데이터베이스**.

- [스키마] '[볼륨]/[에디토리얼]/[원본·보정·IG용·썸네일]' 구조 + 파일명에 크레딧 슬러그 포함 — 파일 시스템 자체가 메타데이터.
- [권리 관리] 각 화보의 사용 범위(웹/IG/광고 2차 활용 가능 여부)를 기록해 광고 소재 선정 시 권리 리스크 사전 차단.
- [재발견] "겨울 무드 + 스튜디오 + 남성복" 같은 조건으로 과거 자산 검색 → 리퍼포징 엔진(07)의 소스 공급처.
- [불변 규칙] 이동·삭제는 항상 계획 목록을 먼저 보여주고 승인 후 실행. 원본은 절대 삭제하지 않음.

### 10 → 살아있는 디자인 시스템 감사관

원본은 시안→명세 1회 변환. 승격판은 **웹사이트 전체의 일관성을 상시 감사**.

- [토큰 추출] pap-styles.css에서 색·타이포·간격 토큰을 추출해 단일 기준표(source of truth) 유지.
- [드리프트 감지] 새 페이지·위젯이 기준표를 벗어나면(하드코딩 색상, 인라인 스타일) 주간 감사에서 자동 적발 — 어드민 위젯 다크박스 사건의 재발 방지 장치.
- [명세 생성] 새 기능 요청 시 기존 토큰만으로 구성된 구현 명세를 선출력 — 개발 속도와 일관성 동시 확보.
- [접근성] 대비율·터치 타깃 크기 기준 미달 요소를 함께 보고 (평점 UI 0건 문제 같은 사용성 이슈 조기 발견).
